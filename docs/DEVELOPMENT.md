# Разработка

## Сборка

Используются .NET 10 SDK, Windows для WPF и PowerShell. Откройте `DroneControl.slnx` или работайте из корня репозитория:

```powershell
dotnet restore DroneControl.slnx
dotnet build DroneControl.slnx -c Release -m:1
```

WPF использует MaterialDesignThemes `5.4.1-ci1521`; это подключённая в проекте prerelease-версия. Мост и консольные тесты не требуют WPF-пакетов. Обновление пакета UI выполняйте отдельно с проверкой ресурсов и фактического запуска окна.

Геймпад использует [SDL3-CS](https://github.com/edwardgushchin/SDL3-CS) `3.4.18` и нативный пакет [SDL3-CS.Windows](https://www.nuget.org/packages/SDL3-CS.Windows/3.4.18.1) `3.4.18.1`. Версии закреплены в csproj. Тестовый runner подключает только чистую модель GamepadInput; SDL не требуется для автоматических проверок осей и центрирования.

Публикация:

```powershell
dotnet publish src/DroneControl -c Release -o dist/DroneControl --self-contained false
dotnet publish src/DroneVideoBridge -c Release -o dist/DroneVideoBridge --self-contained false
```

Распространяйте всю папку публикации, включая SDL3-CS.dll и нативные SDL3.dll в runtimes; отдельного exe недостаточно.

Перед публикацией закройте именно обновляемую программу, иначе Windows может блокировать замену файлов. Эти сборки зависят от установленного runtime и не включают .NET внутрь executable.

## Тесты

```powershell
# Без сети: байтовые векторы, оси, скорость, сброс ввода и HTTP-заголовки в памяти.
dotnet run --project tests/DroneControl.Tests -c Release -- --input-only

# Дополнительно: UDP loopback, таймаут, разные порты, фрагменты и ACK.
dotnet run --project tests/DroneControl.Tests -c Release
```

Это консольный runner: успешно завершённые проверки печатают `PASS`, ошибка бросает исключение и даёт ненулевой код возврата. `dotnet test` не запускает эти проверки. Набор разделён на `VerifyProtocol`, `VerifyFlightInput`, `VerifyGamepadInput`, `VerifyHttpRequestsAsync`, `VerifyTransportAsync`, `VerifyFrameAssembly`.

Полный набор обращается только к `127.0.0.1` на автоматически выбранных портах. В песочнице UDP или служебные named pipes .NET могут быть заблокированы; таймаут такой среды не является доказательством неисправности дрона. Не заменяйте loopback адресом устройства в автоматических тестах.

Тесты не проверяют фактическую реакцию моторов, поведение мыши в реальном окне и длительную устойчивость видеопотока. Полётные проверки выполняются отдельно. Контрольный снимок окна:

```powershell
dotnet dist/DroneControl/DroneControl.dll --render-check docs/window.png
```

Команда открывает окно, сохраняет PNG и закрывает приложение. Она не нажимает «Подключить». Успешная сборка не подменяет визуальную проверку темы и ручную проверку мыши и multitouch.

## Стиль и организация кода

`.editorconfig` задаёт 4 пробела, UTF-8, переносы CRLF, фигурные скобки и развёрнутые блоки. Одна операция — одна строка, состояние имеет содержательные имена. Комментарии объясняют причины и ограничения протокола, а не пересказывают очевидные присваивания.

Общие файлы включены сразу в несколько проектов. Чтобы форматтер не создавал конфликтующие правки linked-файлов, форматируйте проекты последовательно, без одновременного style-fix всего решения:

```powershell
dotnet format whitespace src/DroneControl/DroneControl.csproj --no-restore
dotnet format whitespace src/DroneVideoBridge/DroneVideoBridge.csproj --no-restore
dotnet format whitespace tests/DroneControl.Tests/DroneControl.Tests.csproj --no-restore
```

Не форматируйте `analysis/`, `bin/`, `obj/`, `dist/`: там декомпиляция, временные данные или сборочные результаты. Сгенерированные файлы не редактируются вручную. Исходные таблицы JPEG в `Headers` сохраняйте побайтно.

## Изменение интерфейса

- Тема: `App.xaml`, сейчас Dark / DeepPurple / Lime.
- Общие стили: `Styles/Controls.xaml`, наследуются от Material Design.
- Разметка: `MainWindow.xaml`.
- События окна: `MainWindow.xaml.cs`.

Не удаляйте обработку отпускания мыши/касания, потери захвата в `Controls/Joystick` и `Deactivated` окна: они сбрасывают ввод. Кнопку остановки держите вне прокручиваемого контейнера. Не меняйте сетевой код только ради оформления XAML.

## Скрипты

| Скрипт | Назначение и побочные эффекты |
|---|---|
| Run.ps1 | Собирает и запускает WPF; пишет стандартные bin/obj |
| Start-VideoBridge.ps1 | Запускает опубликованный мост скрытым процессом; не запускает второй экземпляр по тому же пути |
| Stop-VideoBridge.ps1 | Завершает только процесс моста с путём из dist текущего проекта |
| tools/Probe-Video.ps1 | Проверяет TCP 554/7070 и отправляет видеоприветствие UDP 8800; сохраняет первые 8 пакетов в analysis/live |

Probe требует PowerShell 7, адрес компьютера `192.168.169.2` и подключённый дрон. Не запускайте его как часть обычной сборки. Он не формирует полётных команд, но начинает запрос видео и может конкурировать с другим клиентом.

## Ограничения и следующие изменения

- Код протокола компилируется через linked-файлы; при росте проекта можно выделить отдельную библиотеку.
- `Responding` означает свежесть пакета, а не готовность к взлёту.
- `DroneLink` не переподключается после ошибки приёма; требуется переподключение из UI.
- ACK и сборка видео реализуют ограниченный поднабор native-протокола.
- Изменение управления, ACK или границ парсера требует тестов по известным пакетам и отдельной проверки на оборудовании.

## Проверка экранных стиков

Автотесты проверяют знаки четырёх осей, диагонали, одновременный ввод, пропорциональность и скорость. Касания двумя пальцами и реакцию дрона проверяйте отдельно.

Ручная проверка: отпускание мыши за пределами стика; перехват мыши другим контролом; удержание двух пальцев и отпускание одного; Alt+Tab во время ввода. После потери фокуса Armed должен быть снят, обе пары осей — нейтральны.

## Проверка геймпада

`VerifyGamepadInput` проверяет инверсию SDL-Y, оба знаковых предела, мёртвую зону, пропорциональность, сочетание осей и 300 мс непрерывного центрирования. Также проверяются сброс, отключение и смена устройства. Это проверки модели, не драйвера Bluetooth.

Для ручной проверки выберите «Геймпад», оставив дрон отключённым: должны появиться имя контроллера и движение индикаторов. Проверьте отключение/включение контроллера и смену источника; разрешение управления не должно восстанавливаться самостоятельно. В среде с ограничениями доступа к HID обнаружение может вернуть пустой список, хотя обычное настольное приложение видит устройство.

Контракты SDL: [диапазоны и направление осей](https://wiki.libsdl.org/SDL3/SDL_GetGamepadAxis), [ручное обновление состояния](https://wiki.libsdl.org/SDL3/SDL_UpdateGamepads). Собственный список сырых HID-раскладок не поддерживается; при неподдерживаемой модели сначала проверяйте базу mappings и версию SDL.

HTTP-парсер тестируется на заголовках, разбитых на короткие фрагменты, неверном пути, преждевременном EOF и строке длиннее 8 КиБ. UDP-тесты используют реальные BL-пакеты на loopback; режима симуляции в рабочем транспорте нет. Отдельные проверки подтверждают немедленный сброс Responding при ошибке обработчика и повторное закрытие соединения.
